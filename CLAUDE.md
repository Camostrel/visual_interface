# CLAUDE.md — ARVID Visual Interface

## Что это за проект

Потребительский веб-интерфейс к системе умного здания на Home Assistant (ядро — DALI).
**Форк** старого `web_interface` (база v0.9.2): проверенная мобильная вёрстка сохранена,
функциональность вычищена под узкий скоуп. Текущая версия фронта: **v0.14.0**, backend **v0.2.0**.

Документация — в папке [docs/](docs/):
[ARCHITECTURE.md](docs/ARCHITECTURE.md) (модули, потоки, зависимости) ·
[REQUIREMENTS.md](docs/REQUIREMENTS.md) (требование → как реализовано) ·
[ROADMAP.md](docs/ROADMAP.md) (фазы) · [DEBT.md](docs/DEBT.md) (долги + задачи на HA) ·
[DESIGN.md](docs/DESIGN.md) · [SVG_PLAN_SPEC.md](docs/SVG_PLAN_SPEC.md) (эталон плана из CAD) ·
[PLAN_CONVEYOR_DXF_RESEARCH.md](docs/PLAN_CONVEYOR_DXF_RESEARCH.md) (исследование DXF+SVG конвейера + §10 что подтверждено кодом) ·
[DEPLOY.md](docs/DEPLOY.md) · [CHANGELOG.md](docs/CHANGELOG.md).

Работаем **только** в этом каталоге: `/home/user/nicksha/visual_interface/`.
Старый `web_interface` — заморожен, используется только как справка (не менять!).
`arvid-web-interface` — предыдущая попытка с нуля, тоже только справка.

### Скоуп (строго, см. DESIGN.md)

- **Свет** — вкл/выкл/яркость (лампы `light.l_*` и DALI-группы)
- **Датчики движения и освещённости** — мониторинг (`sensor.ms_*` / `sensor.il_*`,
  одно физическое устройство = две сущности)
- **Кнопочные и поворотные панели** — активность/события (`event.kp_*`)

**НЕ тащим:** климат, температуру, CO₂, влажность, шторы, кондиционеры, сценарии,
энергомониторинг, здоровье, погоду — пока осознанно не решим иначе.
Слоты вёрстки «Сводка/Расписание/Предупреждения/Режимы» сохранены — наполняем их
только сигналами нашего скоупа.

### Связь с ядром DALI

Работаем поверх **стандартных HA-сущностей** (`subscribe_entities`, `light.*` сервисы)
+ узкого набора **read-only** WS-команд `arvid_dali_center/*` (основная — push-подписка
`health_subscribe`; `health_data` — фолбэк для старого ядра).
Карта источников и эндпоинтов — [WEB_INTERFACE_API.md](docs/WEB_INTERFACE_API.md).
Контракт v1 и ключевые решения — [DESIGN.md](docs/DESIGN.md).
Ядро DALI живёт в `/home/user/nicksha/arvid-ha-dali-center/` — только для чтения/справки.
Admin-ядро пусконаладки (`arvid-dali-panel`) не трогаем.

## SPA-архитектура (унаследована от базы — НЕ ломать)

`index.html` содержит два view-контейнера: `data-spa-view="floor" | "room"`.
Неактивные views скрыты через `hidden`. Переключение без перезагрузки страницы.
**На телефоне вся страница не прокручивается** — скроллятся только панели и overlay.

### Маршруты

```
index.html
index.html?floor_id=…
index.html?view=room&area_id=…&floor_id=…
```

### Режим редактирования расстановки (v0.2.0, DESIGN решение 20)

Отдельной страницы редактора НЕТ. Кнопка «Редактор» в шапке комнаты включает режим
(`is-room-editing` на shell): вместо панелей управления — карточка «Расстановка устройств»
(фильтры Все/Свет/Датчики/Панели, список с едиными иконками, «В центр плана»,
«Убрать с плана», «Сохранить разметку»). Перенос: drag на компьютере, тап по плану
на телефоне. При выходе с несохранёнными изменениями — confirm: сохранить или отменить
(перечитка layout из HA). Иконка маркера назначается автоматически по типу устройства.

### Анимации переходов

Нативный **View Transitions API** (Chromium 111+), направления floor↔room (слайд).
Атрибут `data-nav-transition` на `<html>`.

**Критичный нюанс CSS** — селектор без пробела:
```css

/* НЕПРАВИЛЬНО */ :root[…] ::view-transition-old(root) { }
```

### Взаимодействие с зонами карты (v0.5.0, ТЗ заказчика)

- **Короткий тап** по зоне комнаты = вкл/выкл света всего помещения (`toggleRoomLights`).
- **Двойной тап** = переход на план комнаты (различение по таймауту 250 мс в `handleZoneTap`).
- **«Выключить свет этажа»** — быстрое действие правой панели (`[data-floor-lights-off]`).
  Отдельной кнопки поверх карты нет (была в v0.5.0, удалена в v0.6.0 как дублирующая).
- **Quick View удалён в v0.10.2** (был отключён с v0.5.0). Понадобится — сделаем заново
  на текущем функционале; воскрешать старый код не надо (в нём жил обход HA-групп).

### Тап по устройству и различение «тап vs перетаскивание» (v0.11.1)

- **Полламповое управление на плане КОМНАТЫ:** тап по лампе (`.device-marker` ИЛИ `.device-node`
  из CAD) = `light.toggle` этой лампы, удержание = попап яркости. Единый жест — `bindDevicePress`
  (`blockPan:true` у маркеров, `false` у устройств плана). Тонкий контур лампы (`fill:none`) не
  тапабелен — под него кладётся мишень `.device-node-hit` по габаритам. На плане ЭТАЖА лампы пока
  только индикаторы (не кликаются).
- **Панораму НЕ блокируем по цели.** `ArvidSvgPanZoom` больше не отменяет pan, когда палец на зоне
  (зоны на объекте всюду — иначе план не перетащить). Тап и перетаскивание различаются **по сдвигу
  пальца** (порог 8px): ушёл дальше — панорама, «случайный» клик после неё гасит капчер-суппрессор;
  не ушёл — тап. Два пальца = зум. `setPointerCapture` убран (мог перенаправить `click` мимо зоны).
- Маркеры расстановки гасят pan сами (`stopPropagation` в своём `pointerdown`) — они точечные.

### Режимы карты (v0.8.0) — CSS-слой, не ветка в JS

Таб-переключатель `.map-mode-switch` — оверлей **над планом** (не в топбаре: там он не виден на
телефоне). Выставляет `data-map-mode` на `.svg-stage`.

`applyZoneStateClasses()` всегда вешает на зону **все** классы состояния, а видимый слой выбирает CSS:

```
light        → .has-light-on   оранжевый
presence     → .has-motion     зелёный (свет игнорируется)
diagnostics  → линии плана серые; .has-offline — красный пульс; .has-anomaly — янтарный
```

**Не добавлять в JS ветки «если режим X — считать Y».** Смена режима = один атрибут.
Серость карты — цветом линий (`--muted`), **не** `filter: grayscale()` (обесцветит красный пульс).

**Карта вне «Освещения» только смотрит (v0.8.1):** одиночный тап переключает свет лишь в режиме
`light` (`canToggleLightsFromMap()`). Двойной тап (переход в комнату) работает везде.

### Состояния датчика движения — ЛАТИНИЦА от ядра (v1.2.45+; было русским до этого)

`transport/decode.py` ядра с v1.2.45: `no_motion / motion / vacant / occupied / occupied_hold`.
Активны `motion` / `occupied` / `occupied_hold`. До v1.2.45 ядро отдавало русский текст
(«нет движения»/«ДВИЖЕНИЕ»/…) — `isMotionActive()` держит его как совместимость (старое ядро).
⚠ **v0.11.8:** `occupied_hold` («пост.занято») раньше выпадал из активных → режим «Присутствие»
его не видел; добавлен.

⚠ Сравнивать только **полным** значением: `no_motion` содержит подстроку `motion` (как и
«нет движения» ⊃ «движение»).

### Подписка на state_changed — событие обязательно пробрасывать

```js
ARVID_RUNTIME.addStateHandler((event) => this.handleStateChanged(event));  // ПРАВИЛЬНО
ARVID_RUNTIME.addStateHandler(() => this.handleStateChanged());            // молча ломает фильтр
```
`room-page.handleStateChanged(event)` фильтрует по `event.data.entity_id`; без аргумента он
выходит на первой проверке, и комната не обновляется вообще (баг жил до v0.8.1).
Подписка глобальная → фильтр «своих» сущностей зовётся на каждое событие HA, состав комнаты
кешируется в `Set` (`invalidateRoomEntityCache()` при смене комнаты и сохранении разметки).

### Здоровье устройств — истина ядра DALI (v0.8.2, требуется ядро ≥ v1.1.1)

Своей логики offline/аварий **не пишем**. `js/health.js` подписан на
`arvid_dali_center/health_subscribe` (push, read-only, без `require_admin`).

- `kind` → `offline` (пульс) / `anomaly` (янтарь) / `gateway` (строка в «Предупреждениях»).
- **`health_data` с ядра v1.2.5 — дешёвый снимок** (`generated_at`), пересчёта на запрос больше нет
  (раньше форсировал полный обход в петле HA — отсюда старый запрет на поллинг). Поллить теперь можно,
  но подписка предпочтительнее (свежесть без таймера). Поллинг — фолбэк при `unknown_command` (старое ядро).
- ⚠ **Грейс 5 мин — только для устройств.** `gw_offline` ядро ставит через ~1.5 с. Поллинг
  задерживал самое срочное событие.
- ⚠ **Маркер сопоставлять по `device_id`**, не по `entity_id`: пара `ms_`/`il_` — одно устройство
  и один маркер, но ДВЕ записи здоровья с разными `entity_id`.
- Фолбэк резолва area **по имени** не удалять: ≤15 с после рестарта HA `active` приходит из
  персиста без новых полей.
- Ядра нет (`unknown_command` на обоих путях) → модуль отключается, остальные режимы работают.

### Цвета карты (v0.8.2)

Выбор зоны (hover) — **синий** (`--zone-select`), не `--accent`: акцент темы зелёный и путался бы
с движением. Присутствие — зелёный пульс 2.6 с, диагностика — красный 1.7 с (авария мигает чаще).
На пульсирующих зонах заливку задаёт анимация → выбор показываем синим **контуром**.

### Планы из CAD: устройство объявляет себя само (D2, v0.10.0)

**Два пути координат, они сосуществуют:**

```
расстановка (layout.devices → .device-marker)  — частные объекты, десятки устройств
план        (data-entity    → .device-node)    — продакшн: чертёж из CAD, сотни устройств
```

Конвейер (правила — [SVG_PLAN_SPEC.md](docs/SVG_PLAN_SPEC.md)):
```
AutoCAD → PDF → SVG (Inkscape)
  → python3 tools/plan_convert.py исходник.svg -o assets/floors/<floor_id>.svg
  → python3 tools/plan_rooms.py assets/floors/<floor_id>.svg -o assets/rooms/
```
Конвертер переносит имя из подписи («L 1.12.31») в геометрию (`data-entity="light.l_1_12_31"`),
снимает цвета (красит тема), схлопывает CAD-трансформации, чистит мусор.

⚠ **Зоны помещений рисуются ВРУЧНУЮ** (слой `ROOM_ZONES`, id = `area_id`): из несвязанных
отрезков стен замкнутые контуры не выводятся, а соответствие «полигон ↔ area» машине неоткуда
взять. Без зон план — подложка, но не карта.

⚠ Устройство есть на плане, но нет в HA → класс `is-unknown`, показываем еле заметным:
серый цвет читался бы как «выключено», а это неправда.

### Зум: помещение «разбивается» на устройства (Фаза 3.5, v0.10.0)

Порог `DEVICE_ZOOM_THRESHOLD = 2.2` → класс `is-zoomed` на `.svg-stage` (колбэк `onZoom`).
Ниже — помещение показывает **агрегат** (зона красится/пульсирует). Выше — зона гаснет до
контура, солируют **устройства**; проблемные пульсируют красным точечно.

**Устройства уже в DOM** (их принёс SVG) → переключение это класс, а не перерисовка.
Не создавать маркеры по зуму: 166 значков этажа в покое ничего не стоят.

### Группы света — НЕ устройства (v0.9.0)

DALI-группа ядра — это тоже сущность `light.*`, и по `entity_id` её от лампы **не отличить**
(имя произвольное, например «r2»). Признак — `ARVID_APP.isLightGroupState()`:

- **DALI-группа ядра:** у её УСТРОЙСТВА в реестре HA `model === "DALI Group"`.
- **Группа/хелпер HA:** в атрибутах список членов `entity_id: [...]`.

Группы **исключены из скоупа**: не лампы, не в карточках, не в редакторе, не на плане.
Иначе счётчик «N/N включено» считает лампу дважды — саму и через группу.
Управление группами живёт отдельно (`getRoomLightGroups()` → селект «Группа света»).

⚠ Не угадывать группу по словам в имени — так было до v0.9.0, ловило лампу «Освещение стола».

### Управление светом — только HA-группы (v0.6.0)

Детерминированный путь: **не собираем лампы поиском**, а дёргаем заранее созданную HA-группу.

```
комната → light.<area_id>_obshchii   (area «512_koridor» → light.512_koridor_obshchii)
этаж    → light.<floor_id>   (этаж «3 этаж» → light.3_etazh)
```

`ARVID_APP.lightGroupState(id)` возвращает состояние группы или `null`. Если группы нет —
фолбэк на сборку ламп + `ARVID_LOG.warn`. Групповая сущность **исключается** из списка
ламп-членов (счётчики «N/N включено»).

### Обновление UI по state_changed (v0.6.0) — ВАЖНО

**Не перерисовывать DOM на каждое событие.** Поток показаний люкс-датчика раньше заставлял
кнопки и слайдер мигать (`renderControls` делал `innerHTML=""`).

Правила:
- `handleStateChanged(event)` — фильтрует чужие сущности и коалесцирует события
  через `requestAnimationFrame`.
- Обновляем **только значения и классы** по якорям: `data-entity` (маркеры),
  `data-light-count`, `data-sensor-anchor`, `data-panel-entity`, `data-mode-entity`.
- Слайдер яркости не трогаем, пока пользователь его держит (`_brightnessInteracting`) или он в фокусе.
- `bindRoomZones()` вызывать только при загрузке плана, **не** по `state_changed`.
- Полный `render*` — при смене комнаты/этажа, входе-выходе из редактирования, сохранении.

### SVG-планы

- Помещения — элементы `.room-zone[data-room-id]`; подсветка (hover / активная /
  `has-light-on` оранжевый при включённом свете) — в `floor.css`, стилей внутри SVG нет.
- Устройства не захардкожены в SVG, создаются динамически по layout/registry;
  координаты — в SVG viewBox.
- Линии планов наследуют цвет темы через `currentColor` (`.arvid-svg-plan { color: var(--svg-plan-line) }`).
- Актуальные планы: `floors/default-floor.svg` (реалистичный этаж, активная зона `ofis`),
  `rooms/ofis.svg` (кабинет ~2:1), `rooms/default-room.svg` (fallback). Пробные удалены.
- Целевой контракт v1 (DESIGN.md): элементы с `data-entity="<entity_id>"` прямо в SVG
  из DWG-конвейера; режим редактирования в комнате — путь для самостоятельной расстановки.

### Привязка «устройство → комната» (v0.7.0) — истина в HA

- **Состав комнаты** = `ARVID_APP.entitiesForArea(areaId)` — только HA (`entity/device.area_id`).
  По нему: карточки, счётчики «N/N включено», статистика, подсветка зон.
- **Маркеры на плане** = `ARVID_APP.placedEntitiesForRoom(areaId)` — наш layout (координаты).
- `ARVID_APP.entitiesForRoom()` (объединение) — **только** фильтр «свои события» для подписки.
- Размещено на плане, но не привязано в HA → `isUnassignedInRoom()` → маркер приглушён
  (`.device-marker.is-unassigned`) + плашка-предупреждение в комнате. В состав/группу не входит.

Режим редактирования показывает **все** устройства скоупа HA (для расстановки) + поиск.

### Мобильная вёрстка этажа и комнаты (v0.13.1–v0.13.11)

Правило одно: **на телефоне план получает всё место, какое остаётся от управления.**

- **Высоту раздаёт flex, а не проценты.** `height: 100%` не резолвится, когда высоту родителя
  считает flex-раскладка, и SVG тогда берёт высоту по пропорции чертежа — вертикальный коридор
  раздувался до 2700 px и выдавливал карточки за экран. Чертёж в комнате позиционируется
  абсолютом по границам сцены.
- **Место делит потребность, а не пропорция:** карточки берут сколько нужно (потолок 55 %),
  остальное — плану.
- **100 % масштаба = план целиком.** Подгонки «по ширине» нет: при входе видно всё помещение.
- **Тулбар плана — одна кнопка «показать целиком»** в правом нижнем углу; масштаб меняется
  щипком и колесом.
- **Режимы карты живут в шапке этажа** (иконки: лампа / идущий человек / линия пульса),
  там же выбор этажа селектором и переключатель темы. Отдельной полосы с этажами нет.
- **Вся правая панель на телефоне свёрнута в одну строку «Опции»**; внутри секции остаются
  свёрнутыми и раскрываются по одной. Раскрытие анимировано высотой (`display` анимировать
  нельзя), план подхватывает изменение через `ResizeObserver`.
- **Секция с единственным действием — просто кнопка** (`Расписание`), без раскрытия.

### Инварианты, добавленные в v0.11.0

- **Резолв area/device — только через индексы реестра** (`entityIdsByArea` / `entityIdsByDevice`).
  Не возвращать `states.filter(...)`: на объекте это O(N) в горячем пути, а в цикле — O(N²).
- **Состав ≠ состояние.** Значение сущности меняется потоком (`state_changed`, DOM не трогаем);
  СОСТАВ меняется редко (`addCompositionHandler`) — там полная перерисовка уместна.
- **Не отправлять весь layout.** Тема → `updateUi()`, расстановка → `updateDevices()` (только
  изменённые `entity_id`). `saveLayout()` — редкий случай и обязан слать `base_rev`.
- **Обрыв связи должен быть ВИДЕН.** Застывшая картинка, которая выглядит рабочей, опаснее
  честного отказа: плашка «нет связи» + гашение органов управления.

**Модель координат — гибрид (осознанно), оба пути РАБОЧИЕ:**
