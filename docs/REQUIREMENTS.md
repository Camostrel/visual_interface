Живой чек-лист: для каждого требования — **как именно** оно у нас сделано и **где** в коде.
Обновляется вместе с разработкой. Приоритеты и фазы — в [ROADMAP.md](ROADMAP.md),
общая карта модулей — в [ARCHITECTURE.md](ARCHITECTURE.md).

Статусы: ✅ готово · 🟡 частично · 🔴 нет · ⏸ отложено.

## 1. Векторная подложка и движок карты

### 1.1 «Отрисовать 2D-план этажа, только стены» — 🟡

**Как реализовано:** SVG-файл плана лежит в `www/visual_interface/assets/floors/`.
Загружается по формуле: `layout.floors[floorId].svg` → иначе `assets/floors/<floor_id>.svg`
→ иначе fallback `default-floor.svg`. Линии стен рисуются `currentColor` и наследуют цвет темы
(`.arvid-svg-plan { color: var(--svg-plan-line) }`), поэтому план читается и в тёмной, и в светлой.

**Где:** `js/floor-page.js → getFloorSvg()`, `js/svg-utils.js → loadSvgInto()`, `css/room.css` (`.arvid-svg-plan`).

**Что осталось:** сейчас `default-floor.svg` — нарисованный нами тестовый этаж (коридор + кабинеты).
Реальный план объекта (из DWG) — Фаза 3.

### 1.2 «Каждое помещение — замкнутый невидимый полигон (контур)» — ✅

**Как реализовано:** контуры лежат **внутри SVG-файла** — это элементы с классом `room-zone`
и атрибутом `data-room-id="<area_id>"`:

```xml
<g id="room-zones">
  <rect class="room-zone" data-room-id="ofis" x="45" y="415" width="390" height="300"/>
</g>
```

Может быть любой `<path>`/`<polygon>`, не только прямоугольник. Приложение находит их через
`svg.querySelectorAll(".room-zone[data-room-id]")` и навешивает поведение.

> **Важное уточнение (частый вопрос).** Сами **контуры — внутри SVG** (как и было раньше).
> А вот **стилизация вынесена наружу**, в `css/floor.css` (с v0.4.0). Раньше `<style>` с
> `.room-zone` жил внутри каждого SVG-файла — это дублировалось в каждом плане и не знало о теме.
> Теперь SVG отдаёт только геометрию, а внешний вид (прозрачность, hover, подсветка по свету)
> задаёт проект. Поэтому новые планы можно рисовать без стилей — достаточно `class="room-zone"`.

**Где:** SVG-файлы `assets/floors/*.svg`; `js/floor-page.js → bindRoomZones()`; `css/floor.css` (`.room-zone`).

### 1.3 «Механика масштабирования для сенсорных экранов» — ✅

**Как реализовано:** собственный движок `ArvidSvgPanZoom` (без библиотек). Меняет **`viewBox` SVG**,
а не CSS-transform — поэтому координаты устройств остаются в системе плана и не «плывут».

| Жест / элемент | Что делает |
|---|---|
| Колесо мыши | зум к точке курсора |
| Перетаскивание | панорамирование (`panByScreenDelta`) |
| Щипок двумя пальцами (pinch) | зум к центру между пальцами |
| Кнопки `+` / `−` / `⤢` | зум к центру / сброс масштаба |

Ограничения: `minZoom 0.45`, `maxZoom 18`, шаг `1.22`. Нажатия на интерактивные элементы
(`.room-zone`, `.device-marker`) панорамирование **не** начинают.

**Где:** `js/svg-utils.js → ArvidSvgPanZoom` (`setupPanZoom`, `zoomAt`, `handlePinchZoom`, `bindToolbar`).

## 2. Логика карты и переход

### 2.1 «light=on → контур жёлтый/светлый; off → прозрачный» — ✅

**Как реализовано:** не YAML-правилом (мы не Lovelace), а нативно: на каждое `state_changed`
пересчитывается состояние комнат и на зону вешается класс `has-light-on`, который красит её
**прозрачным оранжевым** (цвет согласован, решение D в ROADMAP).

Истина «свет включён» берётся из **HA-группы комнаты** `light.<area_id>` (если есть),
иначе — «горит хотя бы одна лампа помещения».

**Где:** `js/floor-page.js → applyRoomLightHighlight()`, `getRoomStats()`; `css/floor.css` (`.room-zone.has-light-on`).

### 2.2 «Клик по помещению → план отдельной комнаты» — ✅

Реализовано как **двойной тап** (см. 3.2): открывается view комнаты с её планом.

**Где:** `js/floor-page.js → handleZoneTap()` → `openRoomByArea()`; `js/spa-router.js`.

### 2.3 «Светильники на плане комнаты, отличаются от стен» — ✅

**Как реализовано:** устройства не зашиты в SVG — рисуются поверх плана как SVG-маркеры
(иконка-панель с гравировкой, 48×48 в координатах viewBox) в отдельном слое `#arvid-device-markers`.
Координаты берутся из нашего backend-стора (`layout.devices[entity_id] = {x, y, area_id}`).
Включённая лампа подсвечивается (класс `is-on`: свечение/яркость иконки).

**Где:** `js/room-page.js → renderDeviceMarkers()`; `js/device-ui.js → iconAssetUrl()`;
`assets/icons/{light,motion,panel}.svg`; `css/room.css` (`.device-marker`).

### 2.4 «Кнопка "Выключить весь этаж" в фиксированном месте» — ✅ (в правой панели)

**Как реализовано:** это **быстрое действие** в правой панели («Выключить свет этажа»).
Отдельная плавающая кнопка поверх карты была добавлена в v0.5.0 и **удалена в v0.6.0** как
дублирующая (решение пользователя).

Логика (v0.6.0): гасит **HA-группу этажа** `light.<floor_id>` (например `light.3_etazh`).
Если группы нет — фолбэк: собирает лампы комнат этажа и пишет предупреждение в лог.

**Где:** `js/floor-page.js → turnOffFloorLights()`; `index.html` (`[data-floor-lights-off]`).

## 3. Прямое управление комнатами (без перехода)

### 3.1 «Короткий тап по полигону → вкл/выкл света помещения» — ✅

Переключает **HA-группу комнаты** `light.<area_id>` (детерминированно).
Фолбэк при отсутствии группы — все лампы помещения + предупреждение в лог.

**Где:** `js/floor-page.js → handleZoneTap()` → `toggleRoomLights()`.

### 3.2 «Двойной тап → карточка пространства» — ✅

Различение тапов по таймауту **250 мс**: первый тап ставит таймер (по истечении — свет),
второй тап в окне — отменяет таймер и открывает комнату. На зонах стоит
`touch-action: manipulation`, чтобы браузер не зумил страницу по двойному тапу.

**Где:** `js/floor-page.js → handleZoneTap()`; `css/floor.css` (`.room-zone`).

### 3.3 «(Опц.) Светильники на общем плане при зуме» — 🔴 Фаза 4

Требует чтения `data-entity` из SVG и посегментной подписки — см. техдолг в ARCHITECTURE §8.

## 4. Режимы карты (селектор «Освещение / Присутствие / Диагностика») — 🟡 Фаза 2

**Селектор добавлен (v0.6.1):** в топбаре над планом, справа от селекта этажа
(`[data-map-mode]`). Выбор сохраняется в `floor-page.mapMode` и выставляется как
`data-map-mode` на контейнере плана. **Логики подсветки по режимам пока нет.**

| Режим | Требование | Готовность |
|---|---|---|
| Освещение | полигоны по статусу `light` | ✅ логика есть (см. 2.1), работает всегда |
| Присутствие | зелёный, если есть движение | 🟡 данные есть (`getRoomStats().motionActive`), окраски нет |
| Диагностика | карта серая, красным пульсируют offline | 🔴 нет (v1 = `state === 'unavailable'`) |

**Где:** `index.html` (`[data-map-mode]`), `js/floor-page.js → setMapMode()`.

> На мобильном `.topbar-actions` скрыт (`display:none`), поэтому селект режима на телефоне
> не виден — место для него нужно определить отдельно (вместе с логикой Фазы 2).

## 4.5 Состав комнаты: что откуда берётся (v0.7.0)

Частый вопрос — «почему в комнате N устройств, хотя в HA привязано меньше».

| Что | Источник | Метод |
|---|---|---|
| **Состав комнаты** (карточки, счётчик «N/N включено», статистика) | **только HA**: `entity.area_id` / `device.area_id` | `ARVID_APP.entitiesForArea()` |
| **Маркеры на плане** | наш backend-стор: `layout.devices[id] = {x, y, area_id}` | `ARVID_APP.placedEntitiesForRoom()` |
| Фильтр «свои события» (подписка) | объединение обоих | `ARVID_APP.entitiesForRoom()` |

Если устройство **стоит на плане комнаты, но в HA к ней не привязано** — маркер рисуется
**приглушённым и обесцвеченным**, а в карточках комнаты появляется плашка
«N устр. на плане не привязано к помещению в HA». В состав и в группу света оно не входит.

**Где:** `js/app-state.js → entitiesForArea / placedEntitiesForRoom / isUnassignedInRoom`;
`js/room-page.js → getRoomComposition / getPlacedEntities / buildUnassignedNote`;
`css/room.css` (`.device-marker.is-unassigned`, `.unassigned-note`).

## 5. Управление светом — модель (v0.6.0)

**Принцип: детерминированные HA-группы, а не поиск ламп.**

| Уровень | Сущность-группа | Формула |
|---|---|---|
| Комната | `light.ofis` | `light.<area_id>` (area «Офис» → id `ofis`) |
| Этаж | `light.3_etazh` | `light.<floor_id>` (этаж «3 этаж» → id `3_etazh`) |
| Весь объект | `light.all` | фиксированное имя |

Группы создаются в HA заранее (логические группы из DALI-групп). Если группы нет — код падает
в фолбэк-сборку ламп и пишет `warn` в консоль. Групповая сущность **не считается лампой**
в счётчиках «N/N включено» (исключается по имени).

**Где:** `js/app-state.js → lightGroupState()`; `js/floor-page.js → toggleRoomLights /
turnOffFloorLights / setAllLights`; `js/room-page.js → getLightTargetIds()` («Вся комната»).

## 6. Производительность и обновление UI (v0.6.0)

**Требование (из практики):** не перерисовывать интерфейс на каждое изменение состояния —
поток показаний люкс-датчика заставлял кнопки и слайдер мигать.

**Как реализовано:** разделены **render** (построение DOM) и **update** (только значения):

- `handleStateChanged(event)` фильтрует чужие сущности и **коалесцирует** пачку событий
  в один кадр через `requestAnimationFrame`.
- Обновляются только: классы маркеров (`data-entity`), счётчик «N/N включено»
  (`data-light-count`), показания датчиков (`data-sensor-anchor`), события панелей
  (`data-panel-entity`), классы зон и режимов.
- Слайдер яркости **не трогается**, пока пользователь его удерживает или он в фокусе.
- На этаже `bindRoomZones()` больше **не** вызывается по `state_changed` (раньше перевешивал
  все обработчики на каждое событие).

Полная перерисовка — только при смене комнаты/этажа, входе-выходе из режима редактирования
и сохранении разметки.

**Где:** `js/room-page.js → handleStateChanged/scheduleStateUpdate/updateControlValues/updateDeviceMarkerStates`;
`js/floor-page.js → handleStateChanged/updateModeCards`.
