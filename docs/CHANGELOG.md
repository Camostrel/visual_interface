# Changelog — ARVID Visual Interface

## v0.6.0 — 2026-07-08 — HA-группы света, конец перерисовки UI, docs/

### Исправлено

- **Fix A — мигание кнопок и слайдера при потоке показаний.** `handleStateChanged` вызывал
  полную перестройку DOM (`renderControls` делал `innerHTML=""`), а на этаже ещё и
  `bindRoomZones()` перевешивал все обработчики зон — на **каждое** `state_changed`.
  При включении света поток от люкс-датчика давал десятки перестроек в секунду.
  Разделены **render** (построение) и **update** (только значения):
  - фильтр чужих сущностей + коалесценция событий в один кадр (`requestAnimationFrame`);
  - точечное обновление по якорям `data-entity`, `data-light-count`, `data-sensor-anchor`,
    `data-panel-entity`, `data-mode-entity`;
  - слайдер яркости не трогается, пока пользователь его держит или он в фокусе;
  - `bindRoomZones()` больше не вызывается по `state_changed`.

### Изменено

- **Управление светом — через HA-группы, а не поиск ламп** (детерминированно):
  комната → `light.<area_id>` (например `light.ofis`), этаж → `light.<floor_id>`
  (например `light.3_etazh`). Хелпер `ARVID_APP.lightGroupState()`. Если группы нет —
  фолбэк на сборку ламп + предупреждение в лог. Групповая сущность исключена из счётчиков
  «N/N включено» и из списка ламп-членов. Затронуты: тап по зоне, «Вся комната» в карточке
  освещения, «Выключить свет этажа».
- **Документация переехала в `docs/`** (ARCHITECTURE, DESIGN, DEPLOY, ROADMAP,
  WEB_INTERFACE_API, CHANGELOG). `CLAUDE.md` остался в корне.

### Добавлено

- **docs/REQUIREMENTS.md** — живой чек-лист «требование → как реализовано у нас» с указанием
  файлов и методов (в т.ч. подробно: зум/пан, полигоны помещений, подсветка).

### Удалено

- Фиксированная кнопка «Выключить этаж» поверх карты (v0.5.0) — дублировала быстрое действие
  в правой панели.

## v0.5.0 — 2026-07-08 — модель взаимодействия карты (Фаза 1 ROADMAP)

Прямое управление комнатами с плана этажа + кнопка гашения этажа — ядро DoD заказчика.

### Изменено

- **Короткий тап по зоне комнаты = вкл/выкл света** всего помещения (`toggleRoomLights`).
- **Двойной тап по зоне = переход на план комнаты** (различение по таймауту 250 мс).
- **Quick View (мини-карточка по клику) отключён** — вызов убран из обработчика зон,
  код методов оставлен (вернём при необходимости), по решению A в ROADMAP.
- **«Выключить этаж» переписан на фильтр по этажу** (`getFloorLightEntityIds`): собирает
  `light.*` всех комнат этажа через `entitiesForRoom` (HA area ∪ размещённые). Не требует
  заранее заданной групповой сущности этажа; заранее сформированные группы света попадают сами.

### Добавлено

- **Фиксированная кнопка «Выключить этаж»** поверх карты, вне зум-зоны (ТЗ Task 3).
- `touch-action: manipulation` на зонах и кнопке — двойной тап не зумит страницу на телефоне.

## v0.4.1 — 2026-07-08 — иконки в редакторе, единый датчик, клик-размещение

### Исправлено

- **Fix A — пустые чёрные иконки в редакторе.** Рамка выделения (`rect.device-marker-selection`)
  добавлялась поверх иконки, а CSS-селектор `.device-marker rect:not(.device-marker-hit)`
  заливал её тёмным (специфичность выше `.device-marker-selection`). Исключил selection
  из заливки — иконки в редакторе теперь как на обычной странице.
- **Fix B — датчики движения (`ms_`) не появлялись в списке.** У DALI-датчиков движения
  `device_class` пустой, а `isMotion` ждал его. Добавил распознавание по префиксу `ms_`
  (и `il_` для освещённости). Причина «доступны только il_» устранена.

### Изменено

- **Единый датчик движения+освещённости.** Пара `sensor.ms_*` + `sensor.il_*` — одно
  физическое устройство (общий `device_id`), теперь это **одна точка** на плане и одна
  строка в списках (kind `sensor`, иконка-радар). Показания — оба сразу: движение · lx
  (в карточке комнаты и в попапе маркера). Схлопывание — `collapseToUnits` по `device_id`,
  якорь пары — сущность движения.
- **Fix C — размещение щелчком/тапом.** Раньше клик по плану ставил устройство только на
  телефоне (на ПК — лишь «В центр плана»). Теперь: выбрал устройство → щёлкнул/тапнул по
  месту → появилось (и на ПК, и на телефоне). Клик отличается от панорамирования по сдвигу.

### Новое в API модулей

- `ha-registry`: `getDeviceId(entityId)`, `getEntitiesForDevice(deviceId)` — для связи пары ms_/il_.
- `device-ui`: `isSensor`, единый `markerKind === "sensor"`; `room-page`: `collapseToUnits`,
  `getSensorReadings`, `formatSensorReadings`.

## v0.4.0 — 2026-07-08 — подсветка света, поиск устройств, реалистичные планы, документация

### Добавлено

- **Подсветка зон комнат** (раньше стилей `.room-zone` не было вообще):
  hover и активная зона — акцентная заливка; **комната с включённым светом —
  прозрачный оранжевый** (`.room-zone.has-light-on`, обновляется на каждый `state_changed`).
- **Поиск устройств по названию** в режиме редактирования (поле над списком; фильтрует
  строки локально, не теряя фокус). Ищет по friendly-имени и entity_id.
- **Привязка «устройство → комната» через объединение** HA area ∪ размещённые нами
  (`ARVID_APP.entitiesForRoom`): свет комнаты и подсветка работают даже когда area
  устройствам не заданы (частные объекты).
- **ARCHITECTURE.md** — карта проекта: слои, модули и зависимости, потоки данных,
  backend, внешние зависимости, инварианты, техдолг.

### Изменено

- **Редактор показывает ВСЕ устройства скоупа HA**, а не только area комнаты
  (`getAllScopedEntities`). Причина: на офисе area устройствам не назначены, а расставить
  нужно любое. Фильтр по помещению (area) отложен как идея (нужен, когда area будут заданы).
- Чипы-фильтры по типу (Все/Свет/Датчики/Панели) сохранены.

### Планы (SVG)

- Удалены пробные планы: `floors/test_floor_a|b.svg`, `rooms/office_alpha|meeting_beta|
  hall_gamma|lounge_delta|service_epsilon.svg`.
- `default-floor.svg` — реалистичный этаж: горизонтальный коридор, кабинеты сверху/снизу;
  активна зона «Офис» (`data-room-id="ofis"`), остальные — неактивные.
- `rooms/ofis.svg` — план кабинета «Офис», пропорции ~2:1 (вытянут сверху вниз), пустой.
- `default-room.svg` — обновлён на чистый прямоугольник-fallback.

### Требует действия на HA (иначе зона офиса не кликается)

Привязать area **«Офис»** к этажу: HA → Settings → Areas & Zones → Офис → Floor.
Сейчас `ofis.floor_id = None`, поэтому зона на плане помечается «не на этом этаже».
Опционально: удалить пробные area (`office_alpha` и др.) и этажи `test_floor_*`.

## v0.2.1 — 2026-07-08 — фикс «пустых» маркеров, чистка топбара

### Исправлено

- **Пустые неубираемые иконки на плане комнаты.** Причина: на плане (обычный режим)
  маркеры рисовались для ВСЕХ сущностей помещения (`getRoomEntities`), включая старые
  записи layout вне скоупа (климат/шторы/сцены) — им общий стор `web_interface.layout`
  проставил координаты, а иконок для них уже нет → рисовался пустой кружок. В режиме
  редактирования список берётся из скоупа, поэтому такие устройства нельзя было выбрать
  и «убрать с плана». Фикс: единый фильтр скоупа `getScopedEntities()` и для плана, и для
  редактора — вне-скоупные устройства не рисуются вообще (`getEditableEntities` → `getScopedEntities`).

### Удалено

- Кнопка «Автоматизации» в топбаре главной (была статичной заглушкой без обработчика).

> Первопричину — общий замусоренный layout-стор со старым интерфейсом — закрывает
> переход на собственный backend (в работе, см. CLAUDE.md «Дальнейший путь»).
