# Changelog — ARVID Visual Interface

## v0.13.0 — 2026-08-21 — новый конвейер планов: DXF (смысл) + SVG (графика)

Закрыты долги **A1/A2**. Имя устройства больше не угадывается по близости подписи — оно
**читается из чертежа**: `NAME` — атрибут блока AutoCAD, координата — точка вставки того же
блока. Графику даёт Illustrator-SVG, связывает их единое преобразование координат.

**Инструменты** (`tools/`, вне рантайма):
- `plan_core.py` — общее ядро: чтение DXF/SVG, преобразование, сборка значков;
- `plan_dxf.py` — конвертер: `dxf + svg -> assets/floors/<floor_id>.svg`;
- `plan_probe.py` — приёмка пары ДО конвертации, код возврата 1, если план не годен.

Пробник и конвертер считают одним кодом — иначе приёмка однажды примет план, который
конвертер соберёт иначе.

**Как собирается значок.** Групп устройства в Illustrator-SVG нет: лампа — это `<rect>`,
датчик — `<circle>` + `<text>`, панель — шесть элементов. Захват идёт **по габариту блока**
(определение блока задаёт размер, вставка — масштаб), а редкое пересечение габаритов
(длинный светильник накрывает текст соседнего датчика) разрешается **составом блока**.
Эвристики «чей ближе» в конвейере нет; неоднозначность — отказ, а не правдоподобный результат.

**Зоны помещений** рисуются из полилинии DXF с XData — по фактической геометрии стен, а не
прямоугольником вручную. Этим закрыт остаток Фазы 3.

**Проверено на «5 этаж»** (176 устройств): преобразование — подобие (поворот −0.00006°,
перекос −0.0001°), остаток матчинга **0.0079 px**, захват **217/217**, спорных 0.
Кросс-проверка на зонах, не участвовавших в подгонке, — 0.004–0.0075 px.

**Собран продакшн-план** `assets/floors/5_etazh.svg`: 143 лампы, 31 датчик, 2 панели,
4 помещения (`501_koridor`, `502_koridor`, `503_zal`, `504_rekreatcia`). Файл назван по
`floor_id`: фронт грузит план как `assets/floors/<floor_id>.svg`.

Конвертер **к Home Assistant не обращается** — план универсален и самодостаточен; «нет такой
сущности/area» — забота интерфейса, правильность имён — зона проектировщика. Из данных
чертежа проверяются только дубли `NAME`; `FLOOR` не проверяется (линии по лестнице законно
приходят на план соседнего этажа).

**Мини-планы помещений — тем же конвертером** (`--rooms DIR`): для каждой зоны вырезается
её контур, стены вокруг и устройства **внутри полигона зоны** (не внутри рамки — помещение
не всегда прямоугольник, рамка захватила бы соседей). Координаты не пересчитываются, рамку
задаёт `viewBox`: один и тот же `data-entity` указывает на одно место и на этаже, и в комнате,
двух наборов координат не существует. Стены берутся по пересечению с рамкой, иначе стена
самого помещения, уходящая за край, потерялась бы. Нарезано: `501_koridor` (19 устройств),
`502_koridor` (31), `503_zal` (32), `504_rekreatcia` (11). Старый `tools/plan_rooms.py`
(нарезка планов прежнего формата) остаётся как legacy.

**Исправлено при сборке комнат:** снимая класс Illustrator, конвертер терял вместе с ним
`font-size` — буква внутри значка датчика рисовалась дефолтными 16 px и вылезала за кружок.
Теперь при снятии класса переносятся `stroke-width` и `font-size` (`KEEP_PROPS`), цвет
по-прежнему отдаётся теме.

**Где:** `tools/plan_core.py`, `tools/plan_dxf.py`, `tools/plan_probe.py`,
`assets/floors/5_etazh.svg`, `assets/rooms/50*.svg`, `docs/SVG_PLAN_SPEC.md` (переписана),
`docs/DEBT.md` (A1/A2),
`docs/ROADMAP.md` (Фаза 3), `docs/PLAN_CONVEYOR_DXF_RESEARCH.md` §10. Версия → **v0.13.0**.

## v0.12.1 — 2026-08-18 — переключатель автояркости в комнате

В карточке «Статус датчиков» появился переключатель **«Автояркость» (Вкл/Выкл)** — если в комнате
есть датчик освещённости. Управление — сервис ядра `arvid_dali_center.set_autobrightness {enabled}`
(не admin) с адресацией **по `area_id`**: HA раскрывает область, сервис сам выбирает датчики
освещённости (0202) — адресоваться `ms_` нельзя (ловушка HANDOFF). Состояние читаем из тумблеров
`switch.*_act` датчиков комнаты (их приносит подписка на сегмент, D1) — активная сторона подсвечена,
обновляется по `state_changed`. Оптимистично переключаем сразу, при ошибке сервиса — откат к
реальному состоянию + сообщение.

Тонкую настройку контура (цель-группа, коридор люксов, «скользящая уставка») НЕ трогаем — она
в admin-карточке ядра; снаружи управляем уже настроенным контуром (граница из HANDOFF §9).

**Где:** `js/room-page.js` (`renderAutobrightnessControl`/`setAutobrightness`/`isAutobrightnessOn`,
обновление в `updateControlValues`), `css/room.css`. Версия → **v0.12.1**.

## v0.12.0 — 2026-08-18 — D1: подписка по сегменту (subscribe_entities) вместо «всего HA»

Крупная правка транспорта (долг D1). Раньше старт тянул **все** состояния (`get_states`) и слушал
**весь** HA (`subscribe_events(state_changed)`), фильтруя чужое на клиенте. Теперь просим у HA
**только сущности текущего экрана** (этаж/комната) через `subscribe_entities`. Держит масштаб
полного дома (~4400 сущностей): меньше трафика, памяти и лишних событий. Видимое поведение то же.

### Транспорт (`ha-ws.js`)
- `subscribeEntities(ids, onDecoded)` + `unsubscribeEntities(id)` (`unsubscribe_events`).
- `decodeEntities` — переводчик **сжатого** формата `a`/`c`/`r` (ключи `s/a/lc/lu`, диффы `+`/`-`)
  в привычные state-объекты. Проверен локально (снимок, диффы, `s`-отсутствует, удаление, немутирование prev).
- `subscribe_events(state_changed)` больше не используется — метод убран.

### Реестр (`ha-registry.js`)
- `loadRegistries()` — старт грузит **только реестры** (без `get_states`).
- `replaceStates` (снимок сегмента), `applyEntitiesUpdate` (слияние `+`/`-`, отдаёт «старое→новое»),
  `entityIdsForArea` (состав области по РЕЕСТРУ, не по состояниям — иначе на старте список пуст).
- `updateStateFromEvent`/`removeEntityState` (путь `state_changed`) убраны.

### Рантайм (`app-state.js`)
- `subscribeSegment(ids)` — владелец подписки: отписать старую, подписать новую; первый снимок
  заменяет состояния и перерисовывает состав; изменения → **синтетические** `state_changed`
  существующим обработчикам страниц (форма события та же — `floor-page`/`room-page` не тронуты).
  Реконнект перечитывает реестры и **переподписывает** сегмент (id после обрыва мёртв).
  Страховка: отрисовка не ждёт снимок дольше 4с (экран 24/7 не подвисает).

### Страницы (`floor-page.js`, `room-page.js`)
- Объявляют «свой» набор (`floorSegmentIds`/`roomSegmentIds`: состав зон из реестра ∪ устройства
  плана ∪ группы света ∪ режимы) и зовут `subscribeSegment` после загрузки плана; фильтр «своих»
  событий теперь строится из того же набора (по id, не по состояниям).

### Заодно — детерминированные группы света (решение пользователя)
Убраны **опасные фолбэки** «раскрыть area в список ламп и дёрнуть все». Кнопки управляют **только**
детерминированными HA-группами: комната `light.<area_id>`, этаж `light.<floor_id>` (`x_etazh`),
объект `light.all`. Нет группы → **предупреждение**, лампы поиском не собираем (тяжело для DALI-шины;
и под D1 в реестре только сегмент, а не весь дом). Затронуты `turnOffFloorLights`, `setAllLights`,
`turnOffRoomLights`, `toggleRoomLights`; сборщики `getFloorLightEntityIds`/`getAllLightEntityIds` удалены.

**Где:** `js/ha-ws.js`, `js/ha-registry.js`, `js/app-state.js`, `js/floor-page.js`, `js/room-page.js`;
версия → **v0.12.0**. ⚠ Проверить на объекте (разворот основного пути данных): первичная отрисовка,
живой toggle, присутствие/диагностика (здоровье — отдельная подписка, не затронуто), навигация
этаж↔комната (переподписка), реконнект, кнопки света. Откат — `git revert` + перезаливка (старый путь цел).

## v0.11.6 — 2026-07-15 — не пересобирать план на том же этаже; снапшот убран

**Клик «Главная» / повторный выбор этажа / возврат из комнаты на тот же этаж больше не
перерисовывает план.** Раньше `selectFloor()` **всегда** заново грузил/парсил/вставлял SVG и

**Снапшот мгновенной отрисовки (был в v0.11.4) — УБРАН.** На этом объекте он не давал видимого
эффекта: сокращал только ожидание `loadAll` (тут и так быстро, сотни сущностей), а сама

природа iframe, а не кеш.

**Где:** `js/floor-page.js → selectFloor()` (guard + `_loadedFloorId`);

## v0.11.3 — 2026-07-15 — разбиватель кеша (`?v=версия`), config.js доезжает до сервера

**Проблема (в iframe HA виснет старая версия, план особенно упорно).** HA отдаёт `/local/`
с `Cache-Control: public, max-age=2678400` — **31 день**. Браузер держит старые JS/CSS/SVG
и сам index.html месяц; лечилось только Ctrl+Shift+R / инкогнито. Заголовок ставит HA, из наших
файлов не убрать. Плюс планы грузились с `cache: "force-cache"` — брались из кеша без ревалидации.

**Решение — версия в URL (`?v=<версия>`).** Меняется при каждом деплое → для браузера это новые
файлы → тянет свежие; в пределах версии кеш работает.
- `js/config.js`: единый `APP_VERSION`, `localAsset()` вешает `?v` на SVG-планы, иконки, лого;
- `index.html`: `?v=` на всех `<link>`/`<script>`;
- `js/svg-utils.js`: убран `force-cache` (свежесть даёт `?v`).

**Документ обновляется по F5 в HA или вручную** — без таймеров/автоперезагрузки (по требованию).
Первый раз после включения схемы нужен один Ctrl+Shift+R (текущий кешированный index.html без `?v`).

**Побочно:** config.js теперь **реально заливается** (с сохранением токена на сервере через
python-инъекцию — токен не покидает сервер). Раньше слали только `sed` по `VERSION`, поэтому код
config.js на сервере оставался старым — в частности, `LOG_LEVEL` висел `debug` (логировал каждое
событие HA). Теперь доедет `warn` из v0.11.0.

**Где:** `js/config.js`, `js/svg-utils.js`, `index.html`, `docs/DEPLOY.md` (процедура деплоя config.js + схема кеша).

## v0.11.2 — 2026-07-15 — лампа кликается целиком и в погашенном состоянии

Проверка v0.11.1 на объекте: **горящую** лампу можно тапнуть по всей площади (заливка

## v0.11.1 — 2026-07-14 — полламповое управление на плане + тап vs перетаскивание

⚠ **Проверить на телефоне** (правка интерактивной модели плана — правило CLAUDE.md 7): тап по
лампе, удержание, перетаскивание плана за зону, пинч, двойной тап по зоне (переход в комнату).

### Добавлено — тап по лампе на плане комнаты

Раньше полламповое управление работало **только** на ручной расстановке (`.device-marker`):
короткий тап = toggle лампы, удержание = попап яркости. На плане из CAD (`.device-node`,
продакшн-путь) лампа **не реагировала вовсе** — обработчики кликов на неё не вешались, а тап
по ней начинал панораму.

Теперь устройства плана комнаты кликабельны с тем же поведением:
- **короткий тап по лампе** → `light.toggle` этой лампы;
- **долгое удержание** → попап с ползунком яркости и Вкл/Выкл;
- датчик/панель → попап показаний (как у маркеров).

Логика жеста вынесена в единый `bindDevicePress` (переиспользуется маркерами и планом).
Тонкий контур светильника (`fill:none`) пальцем не поймать — добавлена прозрачная
область-мишень по габаритам устройства (`.device-node-hit`). Лампы, которых нет в HA
(`is-unknown`), некликабельны — не выдаём их за рабочие.

**Пока только план КОМНАТЫ.** На плане этажа лампы при зуме остаются индикаторами диагностики.

### Исправлено — план не перетаскивался пальцем по зоне (важно для объекта)

Панорама плана **не запускалась, если палец попадал на зону помещения** — а на реальном объекте
зоны покрывают почти весь план, поэтому перетащить его было практически нельзя (то же ломало
пинч, начатый на зоне). Причина: `onPointerDown` пан-контроллера отменял pan по цели
(`.room-zone, .device-marker`).

Переделано на **различение «тап vs перетаскивание» по сдвигу пальца** (порог 8px, как везде):
- pan запускается всегда; если палец ушёл дальше порога — это перетаскивание, а «случайный»
  клик по зоне/лампе после него гасится (капчер-суппрессор в контейнере плана);
- если не ушёл — это тап, срабатывает действие зоны/лампы;
- два пальца — заведомо жест (зум).

Убран `setPointerCapture`: pan слушает `window`, а захват мог перенаправить последующий `click`
мимо зоны и сломать тап по помещению. Маркеры расстановки по-прежнему гасят pan сами
(`stopPropagation`), они точечные.

**Проверено симуляцией:** чистый тап → действие без панорамы; дрожь 3px → тап; перетаскивание
40px → панорама без действия; пинч → зум без действия.

**Где:** `js/svg-utils.js` (`onPointerDown`/`onPointerMove` + капчер-суппрессор клика),
`js/room-page.js` (`bindDevicePress`, `bindPlanDeviceEvents`, `addPlanDeviceHitArea`),
`css/floor.css` (`.device-node.is-interactive`, `.device-node-hit`).

Отличить группу по `entity_id` невозможно: у DALI-группы произвольное имя («r2»). Настоящий
признак — **модель устройства в реестре HA**: ядро ставит `model = "DALI Group"`
(`light.py → DaliGroupLight.device_info`). Добавлен `ARVID_APP.isLightGroupState()`:

- **DALI-группа ядра** → `model === "DALI Group"` у устройства;
- **группа/хелпер HA** (`light.<area_id>`, `light.<floor_id>`, `light.all`) → в атрибутах есть
  список членов `entity_id: [...]`.

Группы теперь **исключены из скоупа устройств** целиком: не считаются лампами, не попадают в
карточки, в редактор расстановки и на план. Управление группами не пострадало — селект
«Группа света» берёт их отдельным методом `getRoomLightGroups()`.

**Заодно снесена эвристика `isLightGroup()`**, которая угадывала группу по словам в имени
(«группа», «all», «освещение», «group»). Она ловила лампу с именем «Освещение стола» и
пропускала DALI-группу «r2».

### Исправлено — `turnOffRoomLights()` шёл в обход HA-групп

Кнопка «Выключить свет» в сводке этажа была единственным местом, которое собирало лампы поиском
вместо HA-группы — тихо, без фолбэк-предупреждения. Приведена к общей схеме:
группа `light.<area_id>` → фолбэк на лампы + `warn`.

Фолбэк «весь свет» (`getAllLightEntityIds`) теперь тоже отсеивает группы: раньше команда уходила
и в группу, и в её же лампы — двойная работа по шине.

### Добавлено — D6: честный offline в комнате

Данные — снимок ядра (`health_subscribe`), своей логики `unavailable` не ведём.

- **Маркер на плане:** не на связи → приглушён, обесцвечен, красное кольцо. Аномалия
  (залипшее движение, «мёртвый» люкс) → янтарное кольцо. Пульс не ставим: маркеров в комнате
  много, мигание превратилось бы в шум (на этаже пульсирует зона).
- **Карточки:** плашка «N устр. не на связи» со списком имён; строки датчиков и панелей
  недоступных устройств приглушены и показывают «не на связи» вместо устаревших показаний.
- **Управление блокируется**, когда ни одна лампа комнаты не на связи (управлять нечем).

> ⚠ **Сопоставление — по `device_id`, не по `entity_id`.** Пара движение+люкс — одно устройство
> HA и **один** маркер (координата лежит под `ms_`), но **две** записи здоровья с разными
> `entity_id`. По `entity_id` ошибка люкса (`sensor.il_*`) до маркера бы не доехала.

`ArvidHealth`: `setUpdateHandler` → **`addUpdateHandler`** (Set). Подписчиков теперь двое —
этаж и комната, единственный обработчик они бы затирали друг у друга.

Комната перерисовывает карточки только когда **состав недоступных реально изменился**
(отпечаток `getOfflineSignature()`), иначе push'и дёргали бы DOM.

## v0.8.1 — 2026-07-10 — реалтайм починен, движение читается верно, карта только смотрит

Разбор после первой проверки v0.8.0 на объекте. Два бага **существовали до Фазы 2** и просто
стали заметны, когда появился режим «Присутствие».

### Исправлено

- **Fix B — движение НИКОГДА не считалось активным.** `ArvidDeviceUi.isMotionActive()` сверял
  состояние с `motion` / `occupancy` / `no_motion` / `vacant` — «по договорённости ядра». Такой
  договорённости в коде ядра нет: `transport/decode.py` отдаёт **русский текст**
  `{1:"нет движения", 2:"ДВИЖЕНИЕ", 3:"свободно", 4:"занято", 5:"пост.занято"}`.
  Ни одно значение не совпадало → функция всегда возвращала `false`.
  Следствия: режим «Присутствие» не красил зоны (не мог в принципе), сводка этажа «Движение»
  всегда показывала 0, в комнате «Движение: нет», маркер датчика никогда не подсвечивался.
  Активными считаем `ДВИЖЕНИЕ` / `занято` / `пост.занято`.
  > ⚠ Сравнивать только **полным** значением: «нет движения» содержит подстроку «движение»,
  > поэтому любой `includes("движ")` даст ложное срабатывание.

- **Fix C — комната не обновлялась по `state_changed` вообще.** В `room-page.js` подписка была
  `addStateHandler(() => this.handleStateChanged())` — стрелка **без аргумента**, поэтому
  `handleStateChanged(event)` получал `undefined`, читал `event?.data?.entity_id` и выходил на
  первой же проверке. Люксы, движение и счётчик «N/N включено» обновлялись только при перезаходе
  в комнату. Теперь событие пробрасывается: `addStateHandler((event) => this.handleStateChanged(event))`.

- **Fix D — кеш состава комнаты.** Подписка на `state_changed` глобальная, поэтому
  `isRoomEntityId()` зовётся на **каждое** событие HA, а он пересобирал состав комнаты
  (полный резолв area по всем сущностям). Из-за Fix C этот путь никогда не исполнялся — после
  починки стал бы горячим. Состав кешируется в `Set`, сбрасывается при смене комнаты и после
  сохранения разметки.

### Изменено

- **Карта вне «Освещения» — только смотрит.** Одиночный тап по зоне переключал свет в любом

  Теперь `some()` по всем датчикам движения помещения.

### Решения (важно для понимания)

- **Диагностику не считаем сами.** Ядро уже ведёт таксономию ошибок (`HEALTH.md`): `lamp_offline`,
  `lamp_unknown`, `sensor_unknown`, `panel_unknown` → «не на связи» (красный пульс);
  `motion_stuck`, `motion_idle`, `lux_stale` → «аномалия» (янтарный); `gw_offline` → строка в
  «Предупреждениях» (шлюз к помещению не привязан).
- **Частота опроса.** У health нет push-канала, только снимок. Ядро не считает устройство
  сломанным первые `grace = interval_min` (**5 минут**) — защита от транзиентов при рестарте.
  Значит опрашивать чаще бессмысленно: в фоне **300 с**, в режиме «Диагностика» **30 с**
  (чтобы починенная зона гасла быстро), при скрытой вкладке — пауза, при возврате — свежий снимок.
- **Серость карты** сделана цветом линий плана (`--muted`), а **не** `filter: grayscale()`:
  фильтр обесцветил бы и сам красный пульс.
- **Деградация без ядра.** `unknown_command` → модуль выключается, поллинг останавливается,
  «Предупреждения» показывают «Данные о здоровье недоступны», режимы Освещение/Присутствие
  работают как обычно. Обрыв WS — временная ошибка, снимок сохраняется, поллинг живёт.

### Известное ограничение

`health_data` отдаёт **имя** помещения (`area.name`), а не `area_id`. Зоны плана живут по
`area_id`, поэтому имя резолвится через реестр HA; **дубли имён** сопоставить нельзя (уходят в
счётчик «Без помещения» + `warn` в лог). Запрос к ядру — добавить `area_id`/`floor_id`/`entity_id`
в записи (**H6** в [DEBT.md](DEBT.md)); код подхватит поле без правок.
