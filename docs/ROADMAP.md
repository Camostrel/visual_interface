# ROADMAP — ARVID Visual Interface

Сопоставление чек-листа заказчика (карта диспетчера) с реальным состоянием проекта
и план работ. Актуально на **v0.4.1 (2026-07-08)**.

## 0. Важное про ментальную модель

Чек-лист написан в терминах **Home Assistant / Lovelace** («YAML-правило для карты»,
floorplan-дашборд). Наш проект — **отдельное SPA на `/local/`, не Lovelace**. Та же логика
(подсветка полигонов по состоянию) реализуется у нас **нативно (CSS/JS по `state_changed`)**,
а не YAML-карточкой. Для диспетчера поведение идентично; физического YAML-правила не будет.
Это надо согласовать с заказчиком, чтобы не искал YAML-файл.

Легенда статусов: ✅ готово · 🟡 частично · 🔴 нет.

## 2. Итог сопоставления

**Сильная база уже есть:** SVG-карта с полигонами комнат, зум для сенсорных, подсветка по
свету в реальном времени, переход в комнату, расстановка и управление светильниками, единый
датчик движения+освещённости.

**Ключевые расхождения (что делать):**
1. **Модель взаимодействия карты** отличается: у нас тап → Quick View, у заказчика тап → toggle,
   двойной тап → переход. Это ядро DoD.
2. **Режимы карты** (Освещение/Присутствие/Диагностика) — новая крупная фича. Данные для двух из
   трёх режимов уже есть.
3. **Диагностика** требует статуса offline/health, которого пока нет.
4. **Кнопка «Выключить этаж»** — есть функция, нужны размещение и надёжность.

## 3. План по фазам (приоритет — по DoD заказчика)

### Фаза 1 — Модель взаимодействия карты  (ядро DoD) — ✅ СДЕЛАНО (v0.5.0)
- ✅ Короткий тап по зоне = **toggle света комнаты** (свет всех ламп помещения).
- ✅ Двойной тап = **переход в комнату** (детальное управление).
- ✅ Quick View отключён (код оставлен) — решение A.
- ✅ **Фикс-кнопка «Выключить этаж»** поверх карты (вне зум-зоны); гасит `light.*` всех
  комнат этажа через `entitiesForRoom`.
- ✅ Оттенок — оставлен оранжевый (решение D).
- **Закрыто:** Task 3 (DoD, кнопка, переход) + «Прямое управление» п.1–2.

### Фаза 2 — Режимы карты (селектор-табы над картой)
- Сегментированный переключатель над планом: **Освещение / Присутствие / Диагностика**.
- Освещение = текущая логика (light on → оранжевый/жёлтый).
- Присутствие = зоны зелёные по `motionActive` (свет игнорируется).
- Диагностика = карта серая, красным пульсируют зоны с `unavailable`/offline (глубина — развилка C).
- **Закрывает:** блок «Дописать логику карты» полностью.

### Фаза 3 — Векторная подложка на реальном объекте
- Реальный план этажа офиса (чистые стены), полигоны-контуры по фактическим помещениям
  (обводка `path`, не прямоугольники).
- Room-план офиса со светильниками по схеме расстановки (механизм уже есть).
- **Закрывает:** Task 2 на реальных данных.

### Фаза 4 — Опциональное / техдолг (низкий приоритет)
- Светильники на общем плане при зуме (чтение `data-entity` из SVG) + замер памяти/быстродействия.
- Переход на `subscribe_entities` по сегменту вместо `loadAll()` — держит масштаб (~4400 устройств).
- Полноценная health-таксономия для «Диагностики» (сверх `unavailable`).

### Фаза 5 — Боевое тестирование / приёмка
- Прогон DoD-сценариев на объекте: гашение этажа в один клик, поиск кабинета, режимы карты.

## 4. Решения по развилкам (согласовано 2026-07-08)

- **A. Quick View → короткий тап = toggle света комнаты, двойной тап = переход в комнату.**
  Quick View пока **отключаем (закомментировать вызов), код не стираем** — вернём при нужде.
- **B. «Выключить этаж» = фильтр по HA-структуре.** Лампам будут заданы пространства (area),
  пространствам — этажи. Кнопка гасит `light.*` всех area текущего этажа (+ размещённые нами
  на планах комнат этажа, через `entitiesForRoom`). Заранее сформированные DALI-группы света —
  тоже `light.*` в area, попадут автоматически.
- **C. «Диагностика» v1 = offline.** Красным пульсируют зоны, где есть устройства в
  `state === 'unavailable'`. Полный health/аварии — позже.
- **D. Цвет «свет включён» — оставляем оранжевый** (текущий `has-light-on`).
