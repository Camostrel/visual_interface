# ROADMAP — ARVID Visual Interface

Сопоставление чек-листа заказчика (карта диспетчера) с реальным состоянием проекта
и план работ. Актуально на **v0.11.6 (2026-07-15)**, задеплоено на HA.

## 0. Важное про ментальную модель

Чек-лист написан в терминах **Home Assistant / Lovelace** («YAML-правило для карты»,
floorplan-дашборд). Наш проект — **отдельное SPA на `/local/`, не Lovelace**. Та же логика
(подсветка полигонов по состоянию) реализуется у нас **нативно (CSS/JS по `state_changed`)**,
а не YAML-карточкой. Для диспетчера поведение идентично; физического YAML-правила не будет.
Это надо согласовать с заказчиком, чтобы не искал YAML-файл.

Легенда статусов: ✅ готово · 🟡 частично · 🔴 нет.

## 2. Итог сопоставления

**Сильная база уже есть:** SVG-карта с полигонами комнат, зум для сенсорных, подсветка по
свету в реальном времени, переход в комнату, расстановка и управление светильниками, единый
датчик движения+освещённости.

**Ключевые расхождения (что делать):**
1. **Модель взаимодействия карты** отличается: у нас тап → Quick View, у заказчика тап → toggle,
   двойной тап → переход. Это ядро DoD.
2. **Режимы карты** (Освещение/Присутствие/Диагностика) — новая крупная фича. Данные для двух из
   трёх режимов уже есть.
3. **Диагностика** требует статуса offline/health, которого пока нет.
4. **Кнопка «Выключить этаж»** — есть функция, нужны размещение и надёжность.

### Фаза 3.5 — Проблемные лампы на плане этажа при зуме — ✅ СДЕЛАНО (v0.10.0)

**Требование.** При проблеме с устройством мигает **помещение** на общем плане. При увеличении
масштаба комната «разбивается» на лампы, и красным выделяются уже конкретные проблемные
светильники — чтобы не входить в помещение. Внутри комнаты поведение продублировать.

**Целевое поведение по уровням зума:**
```
zoom < порога   →  как сейчас: зона комнаты пульсирует красным (агрегат)
zoom ≥ порога   →  зона гаснет, проявляются маркеры устройств комнаты;
                   красным/пульсом — только проблемные, остальные приглушены
в комнате       →  то же самое на room-плане (маркер offline приглушён + красный)
```
Переключение — классом на `.svg-stage` (напр. `is-zoomed-in`) из `ArvidSvgPanZoom` по
`getZoomValue()`, видимость слоёв — CSS. Никакой перерисовки DOM по зуму: слой маркеров этажа
строится один раз при загрузке плана.

**Блокировки сняты, реализовано в v0.10.0:**

1. ~~D2 — `data-entity` в SVG этажа~~ ✅ Устройства приходят из самого плана (конвейер
   AutoCAD→PDF→SVG→`tools/plan_convert.py`). Ручная расстановка на этаже не масштабировалась:
   координаты в нашем сторе заданы в системе **комнатного** плана.
2. ~~H6 — адресация в записях здоровья~~ ✅ снято ядром v1.1.1 (v0.8.2): записи несут
   `entity_id` и `device_id`, клиент их индексирует (`statsForDevice` / `statsForEntity`).

**Как сделано:** элементы устройств уже в DOM (их принёс SVG) → переключение по зуму это класс
`is-zoomed` на контейнере, а не перерисовка. Порог `DEVICE_ZOOM_THRESHOLD = 2.2`.

> ⚠ Красить маркер **по `device_id`**, не по `entity_id`: пара движение+люкс — одно устройство и
> один маркер, но две записи здоровья с разными `entity_id`.

**Побочно закрывает:** D6 (offline в комнате — уже разблокирован), D13.
**Замер:** при появлении маркеров этажа проверить память/быстродействие (пункт ТЗ), связано с D1.

## 4. Решения по развилкам (согласовано 2026-07-08)

- **A. Quick View → короткий тап = toggle света комнаты, двойной тап = переход в комнату.**
  Quick View сперва отключили, затем **удалили в v0.10.2** (мёртвый код). Понадобится — сделаем
  заново на текущем функционале.
- **B. Свет — только через HA-группы** (уточнено в v0.6.x): комната `light.<area_id>`,
  этаж `light.<floor_id>`, объект `light.all`. Группы создаются в HA заранее (логические,
  из DALI-групп). Никакого «поиска всех ламп»; фолбэк-сборка только если группы нет.
- **C. «Диагностика» — уточнено в v0.8.0: источник = ядро, а не наш `unavailable`.**
  Изначально решили считать `state === 'unavailable'` сами. При реализации выяснилось, что ядро
  DALI уже ведёт полноценный мониторинг здоровья (`health_data`, read-only, без admin) — с грейсом
  против транзиентов, длительностями и таксономией из 8 видов. Дублировать это во фронте
  бессмысленно и вредно (наш `unavailable` мигал бы при каждом рестарте HA).
  Итог: красный пульс = «не на связи» (`lamp_offline`, `lamp_unknown`, `sensor_unknown`,
  `panel_unknown`), янтарный = аномалия (`motion_stuck`, `motion_idle`, `lux_stale`),
  `gw_offline` = строка в «Предупреждениях».
- **D. Цвет «свет включён» — оставляем оранжевый** (текущий `has-light-on`).
