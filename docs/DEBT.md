## P0 — найдено аудитом v0.10.2, НЕ починено

> Правки этих долгов лучше компоновать **по месту** (один патч на файл/подсистему),
> а не по одному пункту за раз.

### A1. План может показывать не ту лампу (`tools/plan_convert.py`)
Подпись («L 1.13.7») привязывается к **ближайшему** значку жадным перебором — это не
оптимальное назначение. Прогон реального `3_etazh.svg`: у **162 подписей из 166** в радиусе
60 ед. больше одного кандидата, у 8 отрыв от второго кандидата **< 5 ед.** (минимум 0.9 у
`ms_1_13_1`). Сдвиг подписи в CAD на единицу переворачивает привязку → `data-entity` садится
на соседний светильник, и тап по лампе на плане гасит другую.

**Контроль качества не срабатывает никогда:** порог «подозрительно» = `0.8 × 60 = 48` ед.,
а фактический максимум расстояния на этом плане — 31.2 ед. Отчёт печатает «ПРИВЯЗАНО: 166,
unmatched: 0» и молчит.

**Нужно:** метрика «отрыв от второго кандидата» + варнинг при малом отрыве; проверка взаимной
ближайшести (label→geo и geo→label). **Проверить на объекте:** сверить несколько ламп с натурой.

### A2. Не схлопнутая геометрия уезжает за пределы плана (`tools/plan_convert.py:537`)
`transform` снимается со **слоя безусловно**, а координаты схлопываются только у сматченных
элементов. Значок без подписи, дубль имени, зона без `id`, **любой слой не из четырёх
известных** (двери, размеры, штриховки) — сохраняют относительные координаты и уезжают
на ~126×70 ед. Сейчас не проявилось только потому, что на чертеже ровно 166:166 и лишних
слоёв нет. Это везение, а не инвариант.

### A3. WebSocket не переподключается (`js/ha-ws.js:48`)
Обработчик `close` только пишет в лог. При обрыве (рестарт HA, Wi-Fi, ночь) интерфейс
показывает **застывшую, убедительно выглядящую картинку**: зоны горят, датчики «работают»,
а тапы молча отваливаются (`send` реджектится). Лечится только F5 — диспетчер не догадается.
Для настенного экрана 24/7 это дефект №1. Плюс висящие `pending`-промисы при `close` не
отклоняются (зависшие `await` навсегда).

**Нужно:** реконнект с backoff, повторная подписка (`state_changed` + `health_subscribe`),
видимый индикатор «нет связи», отклонение `pending` при разрыве.

### A4. Layout затирается целиком, без блокировки и версии
Фронт **всегда** шлёт `layout/save` со всем документом из своей вкладки; backend
(`storage.py:121`) пишет его поверх без слияния с сохранённым. В backend классический
read-modify-write **без `asyncio.Lock`** — параллельные сохранения теряют друг друга.

**Сценарий:** пусконаладчик расставил устройства с ноутбука; диспетчер на планшете со старой
вкладкой **переключает тему** (`shell-ui.js:92` шлёт весь layout) → расстановка стёрта. Тихо.

**Нужно:** `asyncio.Lock` вокруг load→mutate→save; версия/etag в `layout/save`; перевести
тему и расстановку на **частичные** `layout/room/update` / `layout/device/update` — они уже
написаны в backend и **не вызываются** (поэтому их не удалили при чистке v0.10.2).

## P1 — блокирует реальный объект

### D1. Загружаем и слушаем «всё сразу»
`ArvidHaRegistry.loadAll()` тянет **все** `get_states` + 4 реестра, а подписка —
глобальный `subscribe_events(state_changed)` на весь HA. На объекте ~4400 устройств это
стоп-фактор (трафик, память, лишние события).

**Целевое** (DESIGN реш. 13): `subscribe_entities` только на сущности текущего сегмента;
их объявляет сам SVG через `data-entity`. Кешировать только статику (SVG/структуру).

**Где:** `js/ha-registry.js → loadAll()`, `js/ha-ws.js → subscribeStateChanged()`, `js/app-state.js`.
**Связано с:** D2.

### ~~D2. `data-entity` из SVG не читается~~ — ✅ ЗАКРЫТ (v0.10.0)
Устройства читаются из самого плана (`data-entity`), и на этаже, и в комнате. Планы из CAD
готовит `tools/plan_convert.py` (docs/SVG_PLAN_SPEC.md).

Два пути координат сосуществуют: **расстановка** (`layout.devices` → `.device-marker`) для
частных объектов и **план** (`data-entity` → `.device-node`) для продакшна.

**Где:** `js/floor-page.js → collectPlanDevices()/updatePlanDeviceStates()`, то же в `room-page.js`.

**Где:** `js/room-page.js → getHealthFor()/renderDeviceMarkers()/buildOfflineNote()`, `css/room.css`.

### D19. `floor-page` не фильтрует чужие события
`ArvidFloorPage.handleStateChanged()` реагирует на **любое** событие HA (подписка глобальная) и в
каждом кадре пересчитывает `getRoomStats()` для всех зон, а каждый вызов — полный резолв area по
всем сущностям (`registry.getEntitiesForArea` = `states.filter`). На тестовом стенде незаметно,
на объекте (~4400 сущностей × N зон в кадр) станет дорого.

В комнате это уже закрыто кешем (v0.8.1, Fix D). На этаже нужен аналог: индекс `area_id → сущности`
в `ArvidHaRegistry`, инвалидация по изменению реестра.

**Где:** `js/floor-page.js → handleStateChanged()/getRoomStats()`, `js/ha-registry.js`.
**Связано с:** D1.

### D20. Квадратичные резолвы в реестре (аудит v0.10.2) — P2
`getEntitiesForArea()` и `getEntitiesForDevice()` — полный `states.filter` по всему реестру,
а зовутся **в циклах**:
- этаж слушает **все** события HA (D19) и на каждое пересчитывает `getRoomStats` для каждой
  зоны **дважды** за кадр (`applyZoneStateClasses` + `renderFloorDashboard`), а внутри —
  `entitiesForArea`. На объекте: ~4400 сущностей × 2 прохода × N зон на **каждое** показание люкса;
- `collapseToUnits` / `getSensorReadings` зовут `getEntitiesForDevice` на каждый датчик →
  **O(N²)**. Тяжелее всего в редакторе расстановки (список строится по всем устройствам HA).

**Нужно:** индексы `area_id → сущности` и `device_id → сущности` в `ArvidHaRegistry` с
инвалидацией по изменению реестра. **Замер памяти на 166 устройствах (пункт ТЗ) делать
ПОСЛЕ индексов** — иначе он измерит уже известную проблему.
Также `updateStateFromEvent()` делает `states.findIndex` (O(N)) на каждое событие, а
удалённые сущности (`new_state = null`) из `stateById` не убираются.

**Связано с:** D1, D19, D5.

### D21. Ошибка маршрута уничтожает вёрстку (аудит v0.10.2) — P2

### D24. Мелочи из аудита v0.10.2 — P3
- **Дубли портретных медиазапросов в `room.css`** (два блока `max-width:760px and portrait`):
  правки в первом молча не работают, побеждает второй. Мина под «святой» мобильной вёрсткой.
- `plan_convert.py`: `stroke-width` читается только из `style` (презентационный атрибут
  выживает в координатах CAD), масштаб толщины — **захардкоженная константа `0.16`** вместо
  значения из матрицы; `viewBox` принудительно обнуляет min-x/min-y (сдвиг плана, если в
  исходнике было смещение) и падает на запятых-разделителях; `rotate(a, cx, cy)` теряет центр
  вращения, `skewX/skewY` молча игнорируются; нет `makedirs` для выходного каталога.
- `plan_rooms.py`: устройства отбираются по **bbox** зоны, а не по контуру. Безопасно, пока
  зоны — прямые `rect`; **станет багом при переходе на зоны по фактической геометрии** (Фаза 3).
- `storage.py`: `layout["meta"]` не-словарь (клиент прислал `{"meta": null}`) → `TypeError`;
  схема `vol` не ограничивает размер и незнакомые ключи layout.
- Поля `building.default_floor_id`, `ui.*_panel_collapsed`, `meta` в сторе **не читаются**
  фронтом; в `ARCHITECTURE.md §5` в структуре стора пропущен `modes` (он есть и используется).
- Не-админ не может сохранить **даже тему** (`layout/save` требует `require_admin`), ошибка
  уходит только в консоль — пользователь ничего не видит. Связано с D15.
