# SVG_PLAN_SPEC — эталон плана этажа

Как должен выглядеть SVG-план, чтобы интерфейс подхватил его без ручной расстановки.
Исходник (из CAD/Inkscape) приводится к эталону скриптом
[tools/plan_convert.py](../tools/plan_convert.py) — вручную ничего править не нужно,
кроме **зон помещений** (см. §4: их из чертежа не вывести).

---

## 1. Зачем эталон

Интерфейс умеет два способа узнать, где на плане устройство:

| Способ | Где координаты | Когда применим |
|---|---|---|
| **Ручная расстановка** (v0.2.0) | наш стор `layout.devices` | частные объекты, десятки устройств |
| **Из SVG** (`data-entity`) | в самом плане | продакшн: сотни устройств, план из CAD |

Эталон — про второй способ. Устройство объявляет себя **сам план**, интерфейс только резолвит
сущность HA по `data-entity` и вешает состояние.

---

## 2. Слои исходника (что рисует проектировщик)

Скрипт ожидает такую структуру (имена слоёв — `inkscape:label`):

| Слой | Что в нём | Обязателен |
|---|---|---|
| `WALLS` | стены, двери, оси — только геометрия | да |
| `LAMP` | прямоугольник/кружок каждого светильника | да |
| `MS` | значок каждого датчика движения+освещённости | нет |
| `KP` | значок каждой кнопочной панели | нет |
| `LAMP_NUMBER` | **текстовые подписи** `L 1.12.31` | да (иначе нечего привязывать) |
| `SENSOR_NUMBER` | подписи `MS 1.13.4` | если есть слой `MS` |

**Ключевое правило проектировщику:** у каждого светильника/датчика на плане **должна быть
текстовая подпись рядом** с его именем в DALI-нотации. Скрипт связывает подпись с ближайшей
геометрией и переносит имя в неё. Сама подпись из плана удаляется.

### Нотация имён (нейминг ядра DALI)

```
L 1.12.31    → l_1_12_31    → light.l_1_12_31
MS 1.13.4    → ms_1_13_4    → sensor.ms_1_13_4
KP 1.5.2     → kp_1_5_2     → event.kp_1_5_2
```
Регистр, пробелы и точки не важны — скрипт нормализует. Важно, чтобы **имя в плане совпадало
с именем устройства в Home Assistant** (его задают на пусконаладке картой
`arvid-dali-commissioning`). Это единственная связь плана с реальностью.

> ⚠ Датчик движения и освещённости — **одно физическое устройство**, на плане одна точка `MS`.
> Люкс-сущность (`sensor.il_*`) отдельной подписи не имеет: интерфейс находит её сам по общему
> `device_id`.

## 3. Что делает скрипт (результат — эталон)

```
исходник CAD/Inkscape  →  tools/plan_convert.py  →  эталонный SVG
```

1. **Переносит имя из подписи в геометрию:**
   ```xml
   <!-- было: два несвязанных элемента -->
   <path id="path1591" d="m 3283,3530 h -19 v -65 h 19 v 65" style="stroke:#f5f5dc"/>
   <text id="l_1_12_31"><tspan>L 1.12.31</tspan></text>

   <!-- стало: одна самодостаточная точка -->
   <g class="device-node device-light" data-entity="light.l_1_12_31">
     <path d="..."/>
   </g>
   ```
2. **Удаляет слои подписей** (`LAMP_NUMBER`, `SENSOR_NUMBER`) — имена теперь в данных.
3. **Заменяет захардкоженные цвета на `currentColor`** — план наследует тему интерфейса
   (см. §5). Исходник может быть каким угодно белым/бежевым, это неважно.
4. **Чистит CAD-мусор:** `sodipodi:*`, `inkscape:*`, неиспользуемые `clipPath`, пустые группы.
5. **Проверяет и отчитывается:** сколько ламп/датчиков привязано, что осталось без пары,
   есть ли зоны помещений.

## 4. Зоны помещений — рисуются ВРУЧНУЮ (один раз)

Скрипт их не создаёт и создать не может: стены в CAD — набор **несвязанных отрезков**,
замкнутые контуры помещений из них не выводятся. Плюс машине неоткуда узнать, какой полигон
соответствует какому помещению в HA.

Без зон план работает как подложка, но **не как карта**: не будет ни подсветки по свету,
ни тапа по помещению, ни режимов Присутствие/Диагностика.

**Что нарисовать в Inkscape** (слой `ROOM_ZONES`): по одному замкнутому контуру на помещение,
`id` = **`area_id` этого помещения в Home Assistant**:

```xml
<g id="room-zones">
  <path class="room-zone" data-room-id="ofis"    d="..."/>
  <rect class="room-zone" data-room-id="peregov" x="45" y="415" width="390" height="300"/>
</g>
```
Форма любая (`path`, `rect`, `polygon`). Заливку и обводку **не задавать** — их рисует
`css/floor.css` по теме и режиму карты. Скрипт проставит `class="room-zone"` сам, если увидит
слой `ROOM_ZONES`; от вас — только геометрия и `id` = area_id.

## 5. Цвета и темы

В эталонном SVG **нет собственных цветов**. Всё через `currentColor`:

| Элемент | Как красится |
|---|---|
| Стены (`.plan-wall`) | `currentColor` ← `--svg-plan-line` (тема) |
| Светильник (`.device-light`) | CSS: серый / оранжевый при включённом / красный при offline |
| Датчик (`.device-sensor`) | CSS: серый / зелёный при движении |
| Зона помещения (`.room-zone`) | CSS: прозрачная / по режиму карты |

Поэтому исходник может быть нарисован любым цветом — скрипт всё равно снимет `stroke`/`fill`
и отдаст управление теме. **Единственное требование: толщины линий (`stroke-width`) сохраняются**,
по ним видно иерархию (несущая стена толще перегородки).

---

## 6. Геометрия и координаты

- **Координаты берутся из SVG**, наш стор `layout.devices` для таких планов не используется.
- CAD-экспорт вешает `transform="matrix(0.16,0,0,-0.16,…)"` на каждый элемент (масштаб + флип
  по Y). Скрипт **схлопывает трансформации** и пересчитывает всё в систему `viewBox` —
  в эталоне трансформаций нет, координаты абсолютные.
- `viewBox` нормализуется к `0 0 W H` (в исходнике бывает сдвиг `translate(-126,-69)`).

## 7. Проверка готового плана

```bash
python3 tools/plan_convert.py план.svg -o assets/floors/2_etazh.svg
```
Скрипт напечатает отчёт. План готов, если:

- [ ] все подписи нашли свою геометрию (`unmatched: 0`);
- [ ] число ламп совпадает с проектом;
- [ ] зоны помещений есть, и каждый `data-room-id` существует как area в HA;
- [ ] имена (`l_1_12_31`) совпадают с именами устройств в HA;
- [ ] план открывается в интерфейсе и в светлой, и в тёмной теме.
